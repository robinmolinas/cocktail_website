# Output Contract — Front-end Payload

The single structured payload the runtime emits and the React/Vite front-end renders directly (CAP-5, CAP-7). One payload per completed quiz. Field names are indicative; lock exact keys with the front-end before build.

**Who writes what:** of the 8 reveal elements, only **#2 emotional fit** and **#6 rationale** are written live by the **Bartender** (the runtime LLM call, which also makes the final personality pick). #1, #4, #5, #7, #8 are **pre-authored** in the 132-store (Tier A). #3 is a **pre-rendered** 3D asset with the name overlaid by the **UI**.

```jsonc
{
  "user": {
    "name": "string",
    "favourite_colour": "string (hex + name, from the quiz colour scale)"
  },
  "personality": {
    "id": "string (e.g. 'explorer-x-sage')",
    "name": "string — the named pairing, e.g. 'The Visionary'",
    "primary": "ArchetypeId",
    "secondary": "ArchetypeId"
  },
  "cocktail": {
    "name": "string",                                 // #1  pre-authored
    "emotional_fit": "string",                        // #2  Bartender (LLM) — 1 sentence, NAMES the personality
    "image_ref": "string",                            // #3  pre-rendered 3D asset id; name overlaid by UI
    "recipe": [ { "ingredient": "string", "quantity": "string" } ], // #4 pre-authored
    "method": [ "ordered step", "..." ],              // #5  pre-authored
    "rationale": [ "beat 1", "beat 2", "beat 3" ],    // #6  Bartender (LLM) — personalized, NAMES the user
    "symbolic_reading": "string",                     // #7  pre-authored
    "serving_ritual": "string"                        // #8  pre-authored
  }
}
```

## The 8 reveal elements (Robin's spec)

| # | Element | Field | Source |
|---|---------|-------|--------|
| 1 | Cocktail name | `cocktail.name` | pre-authored (store) |
| 2 | One-sentence emotional fit (includes the personality name) | `cocktail.emotional_fit` | **Bartender (LLM)** |
| 3 | Image — 3D render + name overlay | `cocktail.image_ref` + `user.name` | pre-rendered + UI |
| 4 | Recipe | `cocktail.recipe` | pre-authored |
| 5 | Method | `cocktail.method` | pre-authored |
| 6 | Rationale — why this drink fits the person & their moment | `cocktail.rationale` | **Bartender (LLM)** |
| 7 | Symbolic reading — what the ingredients & method represent | `cocktail.symbolic_reading` | pre-authored |
| 8 | Serving ritual | `cocktail.serving_ritual` | pre-authored |

## Field rules

- **Every** field populated; no nulls for a successful run.
- `emotional_fit` is exactly one sentence and names the personality (e.g. "The Visionary").
- `rationale` is the personalized, feel-seen narrative (2–3 short beats); it names the user and weaves their own answers. Generated by `../prompts/bartender.md`.
- `symbolic_reading` decodes the ingredients + preparation into meaning — **stable per cocktail, curated in Tier A**, not personalized at runtime. The Bartender may echo it briefly but does not write it.
- `recipe[].ingredient` values are authored for symbolic/experiential fit and mixological coherence — not constrained to a fixed inventory.
- Voice: the *staging* is theatrical/mystical (PRODUCT.md); the Bartender's *words* are intimate, refined, restrained (KB) — not purple.
- `image_ref` points to a pre-rendered asset (separate asset-generation step); the runtime does not generate the image.
