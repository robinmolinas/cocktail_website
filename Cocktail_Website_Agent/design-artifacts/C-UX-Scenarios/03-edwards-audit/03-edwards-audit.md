# 03: Edward's Audit

Created 11 June 2026 · Refreshed 8 October 2026

## Transaction and context

Edward is a creative lead evaluating Robin's work within a few minutes. He judges the same experience as Celeste, using a desktop, developer tools and a mid-range phone. He wants coherent art direction and engineering depth; he fears jank, poor responsiveness and invented results.

## Path and evidence

1. **Entrance:** check the spotlight response, legibility, first-load behavior and Spirit Within promise.
2. **Journey:** test H4 comprehension, H5's distinct rounds, continuous H3 answers, keyboard/touch parity, resize and orientation.
3. **Still Water:** verify a designed reduced-motion path, including untimed H4.
4. **Result:** compare different answer fixtures against authored catalogue text and recipes. A fixed pilot is presentation evidence only.
5. **Failure and privacy:** future remote failure must use the authored fallback silently; trace/diagnostics stay in the browser and the name stays out of the LLM prompt. Shared gifts withhold private readings.
6. **Keepsake:** print from the bottom on phone and desktop; both sheets must be clean. Test gift entry and return to the Entrance.

The planned **taste one already poured** side door leads to an authored house pour. It is Epic 2 work; development jump controls are not that public surface. House readings can knowingly address the shortcut. An LLM failure does not produce an apology and exemplar branch.

## Acceptance boundary

Use measured evidence for smoothness, clean console, text legibility, input equivalence and privacy. The 60fps UI ambition does not imply 60fps video. The old <4s transition ceiling is superseded by approved choreography. Do not describe persistence, OG unfurls or live tailoring as delivered before their checks exist.
