# The Room

Host one pour's conversation among Wren 🪞 (Psychologist), Hester 📜 (Historian) and Tomás 🍸 (Mixologist) until they agree, or honestly can't. Paths: `{pours}` = `{project-root}/Dionysus/Cocktail_Website_Agent/design-artifacts/pours`, `{studio}` = `{pours}/_studio`, `{tools}` = `{project-root}/skills/dps-tools/scripts`. Use `{communication_language}` with Robin.

## Why it works this way
Robin asked for a conversation, not a pipeline: "everyone just chimed in when they believed they could add something… they need to always interact with one another until they agree." The disagreements are where the good work comes from (Hester striking her own legend, Wren catching the Sage's fear of ambiguity, Tomás's too-dry first draft), so the three must be genuinely separate minds, and the record must show their clashes intact. Don't optimise this into a relay, and don't smooth anything over.

## Opening the room
- The feed is the room record: `{studio}/rooms/<pairing>.md`. Open it with one call: `python3 {skill-root}/scripts/room.py open <pairing> --batch <primary> [--menu "<one line from {studio}/menu-assessment.md>"] [--note "<anything else>"]`. It creates the scratch folder `{studio}/work/<pairing>/` (with `_host/`), fills the template, and writes the opening host turn: the pairing and personality, the worked examples, this family's pours so far, the scratch folder, the family plan, Robin's standing notes, and "Four rounds at most". **The family plan comes first:** if `{studio}/plans/<primary>.md` doesn't exist yet, write it before the first room (`references/family-plan.md`). On a rework, open the existing record instead (see `references/batches-and-rework.md`). Don't read the persona sources yourself: that's the agents' work.

## Standing up the three
**Round 1 is Wren's alone** (Robin 2026-09-30: "the psychologist should be the first one to explain who the persona is"). Start her first, in the foreground. Her round-1 turn gives the person in detail (the one true thing no sibling shares, what they hide, fear and give, the siblings, the traps, her story test) and her verdict on the family plan's lead story for this pairing. File it, then start **Hester and Tomás together**, in one parallel call, pointed at Wren's turn file (`_host/r1-wren.md`, read it first) and "Round 2 of 4". Wren comes back in round 3 with their turns. From round 3, all three are brought in every round.

**Story before spec:** Tomás speaks from round 2, with drink ideas and story leads, but writes no spec and runs no balance until Wren has ruled on the story. It's a soft gate: the story can still come from the drink side (ingredient stories), but no drink gets built on a story that's still in doubt. **Exception** (2026-10-01): if Wren accepts the plan's lead in round 1 (even "accept, with conditions"), tell Tomás in his round-2 prompt to build drink v1 (spec, balance, allergens) straight away. In the Ruler rooms he built in parallel with the ruling anyway, and the earlier draft gives the 4-round room back its slack. If Wren replaces the lead, the gate holds as above.

Start each as a separate agent. ## Rounds
**The agents file their own turns** (2026-10-01, after a host copy slip sent Hester a placeholder instead of Wren's turn): each writes its turn to `_host/r{n}-{who}.md` (`who` = wren, hester, tomas; a second turn in the same round is `-2`), and you write yours to `_host/r{n}-host.md`. So the host never retypes a turn. Each round, send each agent, in parallel, only what it hasn't seen yet, **by pointing at those small turn files** (never at the feed): "The new turns are in `_host/r3-host.md`, `_host/r3-wren.md`, `_host/r3-hester.md`; read them first, they're verbatim." Add only what isn't in a file: lint findings addressed to it, and Robin's words if he spoke. End with: "Round {n} of 4. Your turn, or pass. Return ONLY the one status line." (or Robin's budget, or an older room's header budget) Then:
- File the round with one call: `python3 {skill-root}/scripts/room.py turn <pairing> <n> --files host,wren,hester,tomas [--tick "<must-have>"]… [--last-change "…"] [--signoffs "…"] [--objections "…"]` (the order you list is the order they appear; a missing file stops it, so check the agent wrote one; without `--files` it reads the turns on stdin, as before). It stashes each turn in `_host/`, appends the non-pass turns verbatim under `### Round n`, and updates the header. Arrange them so the round reads naturally. Never change a word. Passes aren't written.
- **Addressed questions get answers.** If a turn asks another agent something by name, bring that agent in straight away for a direct reply before the next round.
- **Robin in the room.** If Robin speaks, relay his words verbatim as `👤 **Robin:** …` to all three. They take priority.
- **Keep it moving without steering it.** Your turns are rare and short: stage directions, a lint result, a reminder of what's still missing, a pulled thread ("Wren, Tomás's v2 changes the sherry: does the reading still hold?"). You never argue content, pick winners or write the pour's words.

After every round, update the feed's header:
- **Must-haves:** tick each only when its artifact exists in the scratch folder (or `{studio}/specs/`, `{studio}/fact-cards/`) *and* its owner has presented it in the room. The list: persona read (Wren), story + sourced anchors (Hester), drink + four checks (Tomás), reading (Wren), fact audit (Hester), resonance test (Wren), names ≥3 + pick (all), image brief (Tomás).
- **Last change to the pour:** the round in which any part last changed.
- **Sign-offs:** "I'd put my name to this." counts only if given in or after the last-change round. A later change voids earlier sign-offs, with one exception. **A lint-only fix doesn't void them** (Robin 2026-09-27, "yes for the sign off"). That's a change its owner makes only to clear a lint finding, which changes no fact, no claim and nothing in the drink. File it with a host turn quoting the old and new wording, and note it in the header, e.g. "Wren ✓ r8 · Hester ✓ r7 · Tomás ✓ r7 (r8: lint-only fix, whoYouAre)". Any other change, or any doubt, voids them as before.
- **Open objections:** any "Not yet:" still standing, with its owner.

Once every part exists, assemble a provisional pour and lint it in one call: `python3 {skill-root}/scripts/room.py assemble <pairing>` (see `references/closing-the-pour.md` for `_host/config.json`). Send each finding into the room, addressed to the agent who owns that part.

## Closing, stalls, deadlock
**The room closes** when all eight must-haves are ticked, all three sign-offs are valid, and the lint on the assembled pour has no errors (every warning either fixed or explicitly accepted, in a turn, by the part's owner). Then go to `references/closing-the-pour.md`.

**A stall** means three rounds with no must-have ticked and no part changed. Name the impasse in a host turn and ask each voice for its case in one turn. **Deadlock** means the stall persists for two more rounds, or the budget runs out: **4 rounds for a pour or a rework** (Robin 2026-10-01, down from 5, 6 and before that 7; a room whose header says 7, 6 or 5 keeps it) (Robin 2026-09-30: "we do seven rounds instead of eight, but I need the agents to know that it's only seven so that they feel a sense of urgency"; earlier 8, and 10 before that). The agents know the clock (their `in-the-room.md`), and every round message repeats it. At round 3 (or two rounds before an older room's budget), add a short host turn: one round left, run in four steps; say what's still open, and ask each voice to put its strongest objection in by step 2. If Hester's last check (round 4, step 4) finds something that isn't a quoted wording fix, the budget has run out: flag it. On deadlock, don't break the tie: the pour is `flagged`, with each side's case quoted in the header's open objections. Interactive: offer Robin the choice now, or leave it flagged for his review. Headless: leave it flagged.

## Keeping it lean
Robin 2026-09-27: "let's try to find ways to make it more efficient while maintaining the same level of quality." Every model call re-reads its whole conversation, so the cost is calls × context, for the agents and for you. The voices, the rounds and the audit never get cheaper: only the plumbing does.
- **One call per step** for you: `room.py open`, one `room.py turn` per round, `room.py assemble`, `room.py close`. Don't open the agents' artifacts except to write `config.json`, and take only the lines you need.
- **Point at turn files, never at the feed:** the agents read the new `_host/r{n}-*.md` files, so nobody re-reads the whole record, and nobody pastes turn text back to the host.
- **One session per pour.** Your own context is the largest single cost: in batch creator it reached 570–680k tokens, and every host call re-read all of it. Unattended runs use `scripts/run_unattended.sh`, which starts a fresh headless session for each pour (`resume --one`, see `references/batches-and-rework.md`). Interactive: ask Robin to run `/compact` between pours, or to start a new chat with `/dps-author-pour resume --one`.
- **Tell the agents the assembler's shapes by round 3**, so nothing is lost late. Tomás: `work/<pairing>/mixologist-draft.md` with `## Recipe` as a table (`| amount | item | note |`), `## Method` as numbered lines, `## Checks`, `**closingLine:** *…*`, `## Image brief`, `## Names`. Hester: `historian-anchors.md` (table), audits as `historian-audit*.md`. Wren: `psychologist-reading-vN.md` with its title block and resonance. An alternative paragraph kept inside the reading is counted as an extra "yours": keep alternatives in a separate file.
- **Provisional assemble in round 3**, as soon as a reading, a draft and Hester's audit exist (`assemble` needs a `historian-audit*` file), so lint findings reach their owners with a round to spare. Write `_host/config.json` with the reading's real tagline and epigraph (a placeholder like "TBD" trips the echo check), and mark the other fields `provisional`.
- **Crossings are normal.** Rounds run in parallel, so each reply answers the previous state. Name each crossing in a host turn without picking a side, and say where things now stand. When the story swaps (A moves to B's pick as B moves to A's), ask the one still out of step to rule on the current state. Hester drafting sourced anchors for both options broke one such loop (caregiver-creator).
- **Tick with the header's exact labels:** `persona read`, `story + sourced anchors`, `drink + four checks`, `reading`, `fact audit`, `resonance test`, `names (≥3 + pick)`, `image brief`, e.g. `--tick "names (≥3 + pick)=<name> (all three)"`. Check the header at close and fix any tick that didn't land.
- **Round 4, the last, runs in four steps** (Robin 2026-10-01, when the budget went from 5 to 4: in the Ruler rooms, round 5 only ever landed what the round-4 audit had already quoted, so it folds into round 4). Step 1: Wren and Tomás, in parallel, make every remaining change. Step 2: Hester, with their turns, audits the files as they now stand and quotes any wording still to fix, old → new (citation-only, where it can be). Step 3: Wren and Tomás, in parallel, land exactly those fixes, give their one name and sign on the version they leave. Step 4: Hester confirms on the fixed files, gives her name and signs. Reassemble before step 4 and put the lint result in the host turn. Both audits stay: they're where the quality comes from. Tell the room this in the round-3 host turn.
- **Owners settle crossings.** When two voices cross on a part (the closing line, the epigraph), its owner rules on the current state in their next turn: the words of the reading are Wren's, the facts Hester's, the drink, closing line and image Tomás's. Say so in the round-3 host turn, so a crossing costs no extra round. Names are the room's: a split goes to Robin, flagged. **Hold name picks until the vote** (2026-10-01: in ruler-innocent and ruler-jester each voice switched to the other's pick in the same round, costing a round): tell all three in their first prompt to keep their own pick and write "I could take X" instead of switching; round 4, steps 3 and 4, is the one vote. From ruler-lover on, this settled every name in one vote with no crossing.
- **Late fixes land in step 3.** Quote the audit's remaining wording (old → new) in the step-3 host turn, so a change and its sign-offs land in the same step. A small direct reply between steps (one agent asks another to update a quote) is fine; file it as `-2`.
- **Cut off by a usage limit:** when it resets, SendMessage each agent: "A usage limit cut off your round-N turn; it has reset now. The round-N message above still stands." Their conversation is intact.
- **Measure:** `python3 {skill-root}/scripts/usage.py <session transcript .jsonl> [<pairing>]` gives each room's calls, re-read and output tokens, for the agents and for you. The baseline is batch creator: about 300 agent calls and about 45M tokens re-read per pour, and the host about the same again.

## Several families at once
Robin runs one conversation per family, several at the same time (2026-09-30).
- **Claims:** each family's plan lists the people, stories, bottles and drink shapes it has claimed, and `brief.py --plan` shows the other families' Claims. If a room overturns its plan row, add a one-line note to that row ("room chose …") so the claims stay true.
- **Shared files:** the scripts lock `ingredients.json`, `registry.md` and the index edit in `room.py close`. If you edit `{studio}/index.md` by hand, re-read it just before the edit: another family may have written to it.
- **Keep the host small:** a family conversation hosts eleven pours, and in batch creator the host's context grew to 570–680k tokens. After each pour closes, ask Robin to run `/compact` before the next room opens.
- **Registry:** it shows only closed pours, so pours still open in another family are visible only through that family's plan.

## If the machinery isn't there
- **No SendMessage:** start fresh agents each round with the same prompt. They re-read the feed, so continuity lives in the record.
- **No subagents at all:** voice the three yourself, one at a time, each after loading `{project-root}/skills/dps-agent-{role}/SKILL.md`, that skill's `references/in-the-room.md`, and its sanctum. Write `voiced by one mind (fallback)` in the header, so Robin knows the room wasn't independent.
