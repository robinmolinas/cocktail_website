# Decision log: dps-author-pour

## Session 2026-09-25 (build)

- **Name:** `dps-author-pour` (from the module plan, `skills/reports/dionysus-pour-studio-plan.md`).
- **Classification: complex workflow.** SKILL.md routes; `the-room.md`, `closing-the-pour.md` and `batches-and-rework.md` are carved out because the room mechanics alone would push SKILL.md past its size target. Each carved file restates its paths so it survives compaction.
- **A conversation, not a pipeline** (Robin): no fixed order, everyone chimes in until they agree. Wren usually opens (the person first). Rejected: the plan's first linear order (Wren → Hester → Tomás with fixed challenge rounds), which Robin corrected.
- **Three genuinely separate minds** (Robin wants the room's thinking): three subagents per pour, continued with SendMessage for the whole pour (the standing room, after party mode's agent-team pattern). Fallbacks: fresh agents each round (continuity via the feed), then one mind voicing all three, labelled in the record. Rejected: the host voicing all three by default, because the clashes would be staged.
- **Parallel rounds + addressed replies.** Each round all three see only what's new and speak or pass; a question addressed by name gets an immediate reply. Rejected: a bidding step before every turn (three calls per turn, no gain in naturalness).
- **The feed IS the room record** (Robin reads it). The host's summary at close describes the conversation and never adds content.
- **Closing rule:** eight must-haves ticked (artifact exists *and* its owner presented it) + three valid sign-offs + lint 0 errors on the assembled pour. **A sign-off counts only if given at or after the last change**, so no one's approval carries over to a version they didn't see.
- **Stubbornness** (Robin: "be stubborn"): no host tie-breaks. Stall = 3 rounds without progress; deadlock = 2 more stalled rounds or 16 rounds total → `flagged`, each side's case quoted. **Revised 2026-09-25 (Robin):** budget 10 rounds per pour (5 per rework), and the agents know it ("The Clock" in each in-the-room.md; the host says "Round n of 10"; a two-rounds-left host turn at round 8).
- **The host never writes pour content.** Lint findings go back into the room, to the part's owner. Rejected: host-side auto-fixes.
- **Assembly by the host (LLM), not a script:** the pour format is proven by `lint_pour.py` and the parser, so a separate assembler script would duplicate them. Revisit if assembly errors recur.
- **Fresh room per pour in a batch;** sanctums and studio files carry memory between pours. A batch = one primary archetype (siblings together, for Wren's swap test).
- **Rework:** Robin's direct edits are his words, kept verbatim and never changed back; his notes are the room's first constraint; audit, resonance and lint always rerun.
- **`studio_init.py` added to dps-tools** (idempotent) so the room can bootstrap `_studio/` before the module's setup skill exists. **STUDIO-RULES.md stays at `pours/STUDIO-RULES.md`:** the plan's move into `_studio/` was dropped as a restructure with no benefit (the agents' files already cite both paths).
- **No customize.toml:** ships fixed (the plan has no workflow scalars; paths are the project's).
- **Headless supported** for batches: blockers and deadlocks become flags; JSON returns only paths and status.
- **House pours:** deferred (noted in `batches-and-rework.md`).
