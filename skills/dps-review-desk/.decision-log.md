# Decision log: dps-review-desk

## Session 2026-09-25 (build)

- **Name and brief:** `dps-review-desk`, from the module plan (`skills/reports/dionysus-pour-studio-plan.md`, skill 5). Robin said "let's continue" when offered this build; the plan's section is the spec.
- **Classification: simple workflow.** Export, sync, approve and the follow-ups fit in one SKILL.md; the mechanics live in `scripts/review.py`, so the prompt stays short.
- **Workbook first, reading page later** (plan roadmap step 7). `publish` is left as a stub to build next if Robin wants it.
- **review.py is one script with subcommands** (`setup`, `export`, `status`, `sync`, `note`, `approve`). It reuses dps-tools (`pourfile.py` parser, `lint_pour.lint`, `registry.gather`) instead of re-parsing. It lives in this skill, not dps-tools, because it's the only studio script that needs a non-stdlib package (openpyxl).
- **openpyxl in `pours/_studio/.venv`** (plan: Homebrew's Python blocks system pip; no `uv` on this machine). `review.py setup` creates it with plain python3; everything else runs with the venv's python. Accepted deviation from the builder's `uv run` standard, as in the three agents.
- **Robin's words win, deterministically.** Sync writes changed fields into the pour file with targeted replacements, then re-parses the file and refuses the write if the parse doesn't return exactly what Robin typed (round-trip check). Unchanged fields are never touched, so an export → sync with no edits changes no byte.
- **Nothing Robin wrote can be lost:**
  - Export stops if the workbook holds unsynced changes (`--force` overrides) and always archives the previous workbook to `_studio/review-archive/` first.
  - Sync and export stop while Excel has the workbook open (the `~$review.xlsx` lock file), because unsaved edits would be missed or overwritten.
  - Conflict guard: a row whose pour file changed after export (a rework, an approval in chat) is skipped, and its unapplied edits and notes are kept as desk notes, so they survive the re-export.
- **One safety hold on Robin's approval:** if the same row edits the **recipe**, the approval is held until Tomás updates the spec and the allergen check reruns. Reason: the recipe text isn't linked to the spec, so `contains` (the guest's veto) could silently go wrong. Every other lint finding is reported to Robin and never blocks his approval. Robin can override in chat.
- **Light guard pass** = lint findings that the edit *introduced* (lint before vs after, same file), shown as desk notes in the next export. Hester's check on new factual claims is the workflow's job (an LLM judgement), via her fact-audit capability; the result is added with `review.py note`.
- **Where Robin's words are recorded:**
  - At the top of the pour's room record: `## Robin's review, <date>`, with the decision, the notes and every edit (before → after). This is what Wren's learn-from-edits and the rework read. The first three pours have no room record, so sync creates a minimal one.
  - In the studio-wide ledger `_studio/robin-edits.md` (date, pour, field, before, after, whose ground, learned). Ground: reading fields → Wren; recipe, method, closing line → Tomás; name → all three. The agents read unlearned rows.
- **Notes to the room → rework.** Sync queues each pour with notes (or "Needs work") as a `rework queued` row in `_studio/index.md`; the workflow then offers to run `dps-author-pour rework` for each, and `resume` picks up queued reworks. Approve + notes = approved, notes logged as comments (no rework).
- **Rule candidates:** Accept/Reject in the workbook; sync marks the row in `rule-candidates.md`. Adding an accepted rule to `STUDIO-RULES.md` is done by the workflow (prose in the rulebook's own style), because Robin's acceptance is the approval.
- **Sheet protection** keeps the grey columns read-only (no password; column widths and row heights stay adjustable).
- **No customize.toml:** ships fixed, like the rest of the module.
- **Headless:** supported for `export` and `sync` (JSON out; reworks queued, not run).
- **Checks:** `scripts/tests/test_review.py` 28/28 on a throwaway copy of the pours folder (writer exactness on all pours, export, no-op sync changes no byte, edits/approve/notes, recipe hold, paragraph split/remove, conflict guard, Excel lock, rule candidates, approve in chat). The real studio's files hashed identical before and after the test run. Builder scans: path scan flags only `.decision-log.md` at the root (the builder's own process requires it); script scan: no `uv` for ruff, and no argparse (the script prints its docstring for `--help`, like the dps-tools scripts). Both accepted, as for the other dps skills.
- **Wiring into the studio:** `dps-author-pour/references/batches-and-rework.md` reads Robin's notes from the newest `## Robin's review` section and `resume` runs `rework queued` rows. Wren's learn-from-edits and Hester's and Tomás's memory guidance read `_studio/robin-edits.md` and sign the **learned** column.
- **First real export:** `_studio/review.xlsx` with the four approved pours (2026-09-25).
